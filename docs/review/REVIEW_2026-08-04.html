一、总体评价 #

InterviewOS 是一个本地优先的 AI 模拟面试系统，BYOK + 三处理器（ASR/LLM/TTS）+ WebSocket 实时管道，安全基线显著高于同体量开源项目：AES-256-GCM at-rest、SSRF 多 A 记录 + DNS pin、心跳/打断世代/CSRF/限流/CSP 等一应俱全。

代码整体在「先稳后快」的工程哲学上做到位：协议常量单源、错误响应统一 envelope、阶段元数据 PhaseDef、报告哨兵 CAS、ChatMessage 强类型回放、Trace 中间件上下文传递、self_learning 双层锁都已落地。

近期 commit history（a1153e5 → a415f57）显示项目方已主动完成多次"加固 + 拆分 God"专项,社区工程节奏健康。

主要问题集中在三类：安全纵深仍有 1 处高危（环境变量信任链 + master key 持久化）、部分模块 God 现象仍存（turn_coordinator.py、runner.py、interview/[id]/page.tsx 篇幅大、职责多）、测试与契约一致性仍可补强（前端 WS 协议未跑端到端测试,部分业务路径缺乏单测）。

建议优先级：先收口高危 SSRF/Trust 链与一两条横向扩展性瓶颈（SessionConnection 协议类型化、前端 store 化），再分批处理模块粒度与测试覆盖。

三、安全 (Security) #

3.0 v3 实测发现

⚠
SSRF 4 个测试失败 (pytest 实测) — is_safe_http_url 在以下合法 URL 上返回 False,生产调用 LLM 会被拒:
  • http://api.example.com/v1 (公网 80 端口) — 期望 True,实际 False
  • https://api.example.com:443 — 期望 True,实际 False
  • https://api.example.com:8443 (在白名单) — 期望 True,实际 False
  • https://api.example.com/v1/models?api_key=xxx (含 query) — 期望 True,实际 False
推测根因:socket.getaddrinfo(hostname, None, ...) 未传端口 + urlparse(url).port 对默认端口处理不当。需在 _resolve_all 与 port 白名单逻辑中显式回退 80/443。
🔑
smoke 启动时 master key 路径异常 — fake env 启动后,日志出现 "API Key 解密失败: AES-GCM 解密或认证失败: 密钥可能已变更或数据被篡改"(仅 warning 不阻断),但印证 v2 高危判断:prod 部署如未设 INTERVIEWOS_SECRET_KEY,master 会自动落盘生成,旧密文无法被新 master 解密。

3.1 优势（已落地）

  • ✓ API Key at-rest 加密：AES-256-GCM（cryptography），密文格式 enc:v2:<salt>:<nonce>:<tag>:<ct>，旧 v1 显式抛 LegacySecretFormatError，避免静默迁移误判（app/core/secrets.py）。
  • ✓ SSRF 防御双层：is_safe_http_url 多 A 记录遍历 + IPv6 字面量 + 端口白名单 80/443；PinnedHostTransport 在 httpx transport 层强制改写为 pin IP + SNI 还原，缓解 DNS 重绑定 TOCTOU（app/core/security.py）。
  • ✓ 文件上传 10MB + 魔数嗅探 + 路径越界：PDF/DOCX/DOC magic，assert_within_dir 二次校验；PDF 50 页 / DOCX 200 条目 / 30MB 解压 / 5k 段多重边界（app/api/resume.py、app/services/resume/parser.py）。
  • ✓ WebSocket 守卫：30s 心跳 + 3 miss → graceful close；audio_buffer 5MB；同 session 单连接（fix/ws-single-session-mutex），先鉴权再 claim 租约，防止踢人。
  • ✓ 能力令牌：HttpOnly Cookie + Header + query (dev only)；compare_digest 常量时间比较；cookie-only 可变请求校验 Origin/Referer（CSRF 缓解）。
  • ✓ 日志脱敏：RedactFilter 覆盖 record.msg/args/exc_text 三路径，启发式识别 API Key / Authorization / PEM / 通用 token（app/core/logging.py、app/core/security.py）。
  • ✓ 错误响应统一 envelope：{error:{code,message,trace_id}}，StarletteException / HTTPException / Validation / UnsafeURLError 共用 handler，避免堆栈泄漏。
  • ✓ 限流信任链：仅当 request.client.host 落入 TRUSTED_PROXY_CIDRS（默认仅 loopback）才采 X-Forwarded-For，避免头伪造绕过。

3.2 风险与建议

等级位置问题建议
高 app/core/secrets.py
_load_secret_bytes		 未设置 INTERVIEWOS_SECRET_KEY 时自动生成 data/.secret.key 并落盘；仅 warning 不阻断，prod 误部署存在 「明文机器上能解密所有用户 Key」风险。 prod 模式 is_prod=True 且无环境变量时 启动失败；可由运维显式提供 master key 或 KMS 引用；将生成的文件 chmod 600 已做但无产线验证。
高 app/core/secrets.py
_load_secret_bytes		 环境变量 INTERVIEWOS_SECRET_KEY 接受 base64 或 任意明文字符串；明文模式下 32+ 字节的 raw 直接作为 master 密钥材料使用，没有 KDF。高熵字符串与低熵字符串无差别。攻击者拿到文件 + 弱口令即可解密。 明文路径仍走 PBKDF2-HMAC-SHA256（pbkdf2_hmac），并设置最低熵/长度门槛；文档明确 推荐 base64 32+ 字节。
高 app/api/resume.py
upload_resume		 流式 10MB 上限仅按 chunk 累加；当前 total 单调累加 不在请求级 防御 CPU 耗尽型输入（如超大 PDF 解析开销）。pypdf、python-docx 解析路径的极端输入未做 CPU 预算。 引入 signal.alarm 或解析放在线程池限时；extract_text_from_file 已有页数/条目/字符上限，但解析过程本身可能慢，建议加超时（如 15s）。
中 app/core/ratelimit.py
_resolve_client_ip		 IPv6 字面量解析 ipaddress.ip_address(peer.strip("[]"))，但上游 request.client.host 通常已裸字面量；代理链 IPv6 前缀 […] 实际不会在 X-Forwarded-For 中带括号，基本无影响，但仍应加单测覆盖。 补 test_ratelimit.py 覆盖 IPv6 loopback + 假代理头；增加 IPv6 可信代理 CIDR 示例。
中 app/api/v1/ws_interview.py 未直接读源码，但 app/realtime/connection_lifecycle.py 中 WS 握手在 鉴权失败 时 await self.send("error", ...) 后 未 close，依赖客户端识别 error 消息；可能造成攻击者保持半开 socket。 鉴权失败 立即 await self.ws.close(code=4401)；并避免任何业务逻辑在鉴权后执行。
中 app/services/stt/cloud.py、openai_compat.py 等 多家云 ASR 厂商（阿里/腾讯/百度/讯飞/豆包）的出站 HTTP 调用未走统一的 make_pinned_async_client；_safe_base 校验的是用户填写的 base，但厂商 SDK 内部可能有附加域名。 把厂商 ASR 出站统一经过 pin_safe_http_url；至少加白名单校验或审计每个厂商 SDK 的实际出口域名。
中 app/services/llm/client.py
embed		 embed_key = decrypt_secret(self.api_key) if self.api_key else "" 在 LegacySecretFormatError/ValueError 路径下回退 明文 self.api_key，可能使陈年明文缓存直接外发。 解密失败应 抛 400 或 返回 None，而不是静默回退到原明文。
低 app/api/resume.py 删除简历时使用 upload_dir.glob(f"*_{sanitize_filename(r.filename)}") 模糊匹配，多个不同源简历同名时可能误删。 文件名落盘含 uuid.uuid4().hex[:8]_ 前缀，删除时建议用 Resume.id 反查实际落盘路径并显式记录在 DB 列。
低 app/core/secrets.py
_migrate_legacy_keyfile		 旧 app/data/.secret.key 迁移后仅打 warning，未删除旧文件，存在两份相同 master key。 迁移后 os.remove(_LEGACY_KEYFILE)（保留可选项）或在文档提示运维手动删除。
信息 app/services/search/web.py DuckDuckGo 搜索结果会原样传入 LLM 工具消息，构成 间接 Prompt 注入面。当前仅 _truncate(8000) + warning。 在工具消息前后加显式「以下为外部搜索结果，仅作参考，不应作为可信指令」包裹；或仅在 followup 等特定阶段启用 web_search。
信息 frontend/src/lib/api.ts API 错误消息直接显示服务端 error.message，可能包含内部细节（虽然 envelope 已统一，但 Validation 422 仍可能泄漏字段名）。 在 parseErrorResponse 过滤包含内部堆栈/路径/detail object 的字符串。

四、现代性 (Modernity) #

4.1 亮点

  • ✓ 类型契约强：noUncheckedIndexedAccess、noImplicitOverride、noFallthroughCasesInSwitch；前端 ServerEvent/ClientEvent discriminated union 与后端 enum 字段一一对应；后端 TypeAdapter(list[ChatMessage]) 反序列化校验。
  • ✓ 异步协作合理：报告生成哨兵 CAS、WS 报告后台任务、TTS 队列独立 worker；asyncio.to_thread 包装同步 IO 防事件循环阻塞。
  • ✓ 现代 Web 标准：AsyncIterator、httpx AsyncClient、PinnedHostTransport 自定义 transport、fastapi.WebSocket + Cookie Auth。
  • ✓ SQLAlchemy 2.0 typed：Mapped[T]/mapped_column 全量替换 Column；时区感知 datetime。
  • ✓ 可观测性雏形：trace_id middleware + ContextVar 跨协程传播；JSON 结构化日志（SafeFormatter）。
