## 一、总体评价

InterviewOS 是一个本地优先的 AI 模拟面试系统,BYOK + 三处理器(ASR / LLM / TTS)+ WebSocket 实时管道。

**v3 实测验证**:
- 269 / 273 测试通过(98.5%);4 个 SSRF 边界用例失败
- 类型契约在前端严格、类型契约在后端松散(mypy 262 错,222 个在 mixin 共享宿主字段上)
- 依赖有 1 个后端漏洞(chromadb) + 1 个前端传递依赖漏洞(brace-expansion)

**主要问题集中在四类**:

1. **安全纵深 1 处高危 + 1 处可执行失败**:master key 默认落盘、prod 误部署可全量解密;SSRF 端口白名单 + query string 4 个测试用例当前失败(意味着 `is_safe_http_url` 在某些合法 URL 上会误拒,生产调用 LLM 可能失败)

3. **依赖漏洞**:chromadb 1.5.9 PYSEC-2026-311、brace-expansion HIGH(嵌套在 typescript-estree)
4. **测试覆盖 60%**:低于业界良好实践(70-80%)

## 三、安全(Security)· v3 实测

### 3.1 v3 实测发现的 4 个 SSRF 测试失败

`pytest tests/test_security.py tests/test_security_extra.py` 报告 **4 failed, 71 passed**:

| 失败用例 | 输入 | 期望 | 实际 |
| --- | --- | --- | --- |
| `test_classification[http://api.example.com/v1-False-True]` | `http://api.example.com/v1` (公网 80 端口) | True | **False** |
| `test_non_standard_port_default_rejected` | `https://api.example.com:443` | True | **False** |
| `test_port_whitelist_override` | `https://api.example.com:8443` (在白名单) | True | **False** |
| `test_query_string_with_safe_path` | `https://api.example.com/v1/models?api_key=xxx` | True | **False** |

**问题分析**:`is_safe_http_url` 在 `socket.getaddrinfo(hostname, None, ...)` 时,**无第二个参数(端口)** 会导致返回 socket info 缺 port,后续 `parsed.port` 也可能为 None,但 `urlparse` 对默认端口的解析因 URL 字符串是否带端口而异;测试期望公网 80 端口可达、query string 不影响、显式端口 443 应等价 443 — 当前实现**在生产中可能误拒合法 URL**,导致 LLM 调用失败。

**风险等级**:🟡 中(直接影响生产功能,而非安全漏洞;但 SSRF 防御应该 fail-open 而非 fail-closed 处理合法 URL)。

### 3.2 v3 实测:smoke 启动时的 master key 异常

```
{"msg": "API Key 解密失败: AES-GCM 解密或认证失败：密钥可能已变更或数据被篡改"}
```

测试用 fake `LLM_API_KEY=sk-fake-for-smoke` 与 `INTERVIEWOS_SECRET_KEY` 未设,master 自动落盘生成,数据库中之前测试遗留的 `enc:v2:` 密文无法被这个 fresh master 解密 — 仅 warning 不阻断。**印证 v2 关于"master key 默认落盘 + 未设 env 时静默生成"的高危判断**。
